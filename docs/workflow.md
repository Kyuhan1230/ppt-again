# HTML로 만든 자료에 PPT가 필요할 때

## 해결하려는 문제

AI 도구나 코드로 HTML 장표를 만들었어도, 발표·보고·제출에 PPT 파일이 필요할 수 있습니다. 혼자 준비하는 자료도 PowerPoint에서 문구를 다듬거나 숫자를 바꾸고 싶을 때가 있습니다. 장표를 이미지로 옮기면 이런 부분 수정이 어렵습니다.

Slidehandoff는 HTML로 작성한 자료를 편집 가능한 PPT 파일로 가져오는 데 집중합니다. 작성자 본인이 마무리할 수도 있고, 동료에게 전달할 수도 있습니다. 아래 상황은 제품을 설계할 때 정한 사용 가설이며, 고객 인터뷰 결과가 아닙니다.

| 상황 | 필요한 결과 | 확인 방법 |
| --- | --- | --- |
| 혼자 만든 HTML 자료를 PPT로 제출해야 한다 | 내용을 옮겨 적지 않고 PPT 파일로 받는다 | 파일 열기와 내용·누락 확인 |
| 발표 자료를 PowerPoint에서 다듬고 싶다 | 문구·숫자·기본 도형을 직접 수정한다 | 수정·저장·재열기 |
| 보고 직전에 숫자가 바뀐다 | 해당 숫자를 PPT에서 바로 고친다 | 텍스트 수정 후 저장하고 다시 열기 |
| 동료가 자료를 이어받는다 | 작성자의 도구 없이 문구와 도형을 수정한다 | 인수자가 설명 없이 후속 작업 수행 |
| 매주 보고 내용을 바꾼다 | 수정한 HTML을 다시 출력해도 나머지가 유지된다 | 수정 전후의 비대상 글자·객체 비교 |
| 회사 자료를 사용한다 | 처리 위치와 보관 범위를 이해한다 | 통신·접근·삭제 동작과 안내 대조 |

## 선택한 방식과 그 이유

**앱에서는 HTML을 PPT로 변환합니다.** 사용하던 AI 도구나 편집기로 HTML을 만들고, PPT 파일이 필요한 단계에서 변환합니다. 개발 모듈에는 기본 객체의 PPT → HTML → PPT 변환이 포함되어 있습니다. 역방향 파일 선택·다운로드 화면은 아직 연결하지 않았습니다. 지원 범위와 실행 방법은 [개발 안내](development.md#ppt에서-html로)를 참고하세요.

**글자와 기본 도형은 각각의 객체로 만듭니다.** 장표 전체를 한 장의 이미지로 저장하면 모양은 비슷해도 문구나 숫자를 고치기 어렵습니다. 대신 브라우저와 PowerPoint의 글꼴·줄바꿈 차이를 해결해야 합니다. 복잡한 그림의 내부 편집까지 약속하지 않습니다.

**HTML의 상호작용은 원본에 남습니다.** 브라우저 발표에 쓰는 버튼, 애니메이션, 실시간 계산을 PPT로 재현하는 기능은 없습니다. 현재 변환 대상은 지원 범위 안의 정적 장표이며, 스크립트를 실행해야 나타나는 내용은 지원하지 않습니다.

**처리는 로컬에서 시작합니다.** 문서를 외부 변환 서버에 보내지 않는 구조를 택했습니다. 그만큼 설치 환경과 글꼴의 차이를 안내해야 합니다. 로컬 실행만으로 문서 보호가 완료된 것은 아니므로 접근과 보관 문제를 별도로 확인합니다.

## 효과를 확인하는 기준

아직 시간 절감이나 구매 의향을 측정하지 않았습니다. 사용자 확인 단계에서는 변환 시간만 재지 않습니다. HTML 준비, 변환 실패 대응, PPT 확인과 재작업을 포함한 전체 시간을 기존 방식과 비교할 계획입니다.

초기 확인 항목은 작업 완료 여부, 내용 누락, 수정 가능한 객체, 본인 또는 인수자의 후속 수정, 재작업 시간입니다. 빠르더라도 누락이 생기거나 필요한 내용을 수정할 수 없다면 개선이라고 판단하지 않습니다.

## 프로젝트로 남기려는 근거

업무 개선은 문제와 효과를 설명할 수 있어야 합니다. 이 프로젝트에서는 HTML 자료의 PPT 활용·수정·제출이라는 문제를 정하고, 파일 형식의 차이와 문서 보호를 설계에 반영하며, 확인한 범위와 남은 한계를 구분하는 과정을 남깁니다. 실제 도입 성과나 업무 효율 향상은 사용자 작업을 측정한 뒤 기록합니다.
